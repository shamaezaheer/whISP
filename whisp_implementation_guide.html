Local Development Setup

Step 1 – Clone and configure

git clone <repo-url> whISP
cd whISP
cp .env.example .env
# Edit .env – see §4 for all variables

Step 2 – Start infrastructure services

docker compose up -d postgres redis zookeeper kafka
# Wait ~30 s until all four show "(healthy)"
docker compose ps

Step 3 – Run database migrations

docker compose run --rm api alembic upgrade head

Or locally (Python + deps installed):

cd services/api
pip install -r requirements.txt
PYTHONPATH=. alembic -c ../../alembic.ini upgrade head

Step 4 – Seed development data

docker compose run --rm api python scripts/seed_dev.py
# Creates: 3 franchisees, 5 plans, 100 subscribers

Step 5 – Start application services

docker compose up -d api billing coa-engine notification radius-consumer
docker compose logs -f api
# Expected: database_connected, redis_connected, startup_complete

Step 6 – Start frontend (optional)

# Franchisee CMS
cd frontend/franchisee-cms && npm install && npm run dev   # http://localhost:3000

# User portal (new terminal)
cd frontend/user-portal && npm install && npm run dev      # http://localhost:3001

Verify

curl http://localhost:8000/health
# {"status":"ok","redis":"connected","version":"..."}

Schema Overview

    ├── franchisee_users        (staff login)

    └── subscribers
            ├── payment_transactions

Running Migrations

alembic upgrade head           # apply all pending
alembic current                # show current revision
alembic history --verbose      # full history
alembic downgrade -1           # rollback one step

Creating a New Migration

alembic revision --autogenerate -m "add_field_xyz"
# Edit the generated file in alembic/versions/ to verify
alembic upgrade head
TimescaleDB HypertableThe usage_stats table must be converted to a hypertable after the first migration. Run once manually or in migration 0002:
SELECT create_hypertable('usage_stats', 'time', if_not_exists => TRUE);
SELECT add_retention_policy('usage_stats', INTERVAL '90 days');
SELECT add_compression_policy('usage_stats', INTERVAL '7 days');

6.3 CoA Engine (services/coa-engine)

Sends RFC 5176 Change-of-Authorization packets over UDP to MikroTik routers.

Packet TypeCodeUse
Disconnect-Request40Force PPPoE session termination
CoA-Request43Apply rate-limit (speed throttling)

MikroTik VSA (vendor ID 14988) is used for rate-limit: Mikrotik-Rate-Limit = "10240k/5120k".

Triggered by: subscriber suspension · plan expiry · quota exceeded · payment completion.

6.4 Notification Service (services/notification)

Runs two concurrent async loops:

  • DB drain loop (every 5 s): polls notifications table for pending records, sends via SMS/push, updates status.
  • Kafka consumer loop: consumes real-time events, inserts notification record, sends immediately.

Rate limiting: token-bucket algorithm, default 10 SMS/second.

6.5 RADIUS Consumer (services/radius-consumer)

Kafka topic → TimescaleDB usage ingest.

EventAction
Acct-Status-Type = StartInsert session, mark subscriber online
Acct-Status-Type = Interim-UpdateUpdate quota_used_bytes, check quota limit
Acct-Status-Type = StopMark session ended, write final usage to TimescaleDB

When quota_used_bytes >= plan.quota_gb × 1 073 741 824, a CoA rate-limit request is published.

Payment Gateway Integration

8.1 bKash PGW

Flow:

  1. POST /payments/bkash/initiate → API calls bKash /tokenized/checkout/create → returns bkashURL (redirect user here)
  2. User completes payment on bKash app
  3. bKash calls POST /payments/bkash/callback (IPN) → API calls /tokenized/checkout/execute → if transactionStatus = "Completed": run _complete_subscription()

Sandbox test credentials: customer wallet 01877722345, PIN 12121.

Auto-debit: initiate agreement via /payments/bkash/agreement/create, store returned agreementID in subscribers.bkash_agreement_id. Billing engine charges automatically on renewal.

8.2 Nagad

Nagad uses RSA encryption. Generate a key pair:

openssl genrsa -out nagad_private.pem 2048
openssl rsa -in nagad_private.pem -pubout -out nagad_public.pem
# Base64-encode both for .env
base64 -w 0 nagad_private.pem > nagad_private.b64

Share your public key with Nagad. Put their public key in NAGAD_PUBLIC_KEY and your private key in NAGAD_PRIVATE_KEY (both base64-encoded).

8.3 SSLCommerz

SSLCommerz handles Visa/Mastercard, bKash, Nagad, and Rocket in a single checkout page.

Critical – IPN ValidationSSLCommerz sends a POST to SSLCOMMERZ_IPN_URL. Always verify the val_id against the SSLCommerz validation endpoint before crediting the subscriber. Never skip this in production.

Post-payment flow – _complete_subscription()

Called by all gateway callbacks on success:

1. subscriber.plan_id = plan_id
2. subscriber.quota_used_bytes = 0
3. subscriber.plan_expires_at = now + timedelta(days=plan.validity_days)
4. subscriber.status = "active"
5. await radius_sync(subscriber)       # UPDATE radcheck + radusergroup
6. await coa_reconnect(subscriber)     # CoA-Request or Disconnect+reconnect
7. await provision_ott(subscriber)     # Chorki / Hoichoi if plan includes them
8. await queue_sms(subscriber, "activation")

RADIUS / FreeRADIUS Integration

Shared Database Schema

TablePurpose
radcheckPPPoE credentials (Cleartext-Password)
radusergroupMaps username → plan group
radgroupreplySpeed limits per group (set when creating a Plan)
radacctLive + historical accounting sessions (written by FreeRADIUS)

RADIUS Sync – SQL

-- 1. Upsert credentials
INSERT INTO radcheck (username, attribute, op, value)
VALUES ($1, 'Cleartext-Password', ':=', $2)
ON CONFLICT (username, attribute) DO UPDATE SET value = EXCLUDED.value;

-- 2. Set group (plan)
DELETE FROM radusergroup WHERE username = $1;
INSERT INTO radusergroup (username, groupname, priority) VALUES ($1, $2, 1);

FreeRADIUS Configuration

# sql.conf
server   = "postgres-host"
port     = 5432
login    = "radius_user"
password = "radius_pass"
radius_db = "radius"
# sites-enabled/default
authorize  { sql }
authenticate { Auth-Type PAP { pap } }
accounting  { sql }

MikroTik – Enable CoA

# RouterOS terminal
/radius incoming set accept=yes port=3799
/radius add address=<api-server-ip> secret=<nas_devices.secret> service=ppp
Secret MatchThe secret field in the nas_devices database table must exactly match the RADIUS secret configured on the MikroTik router. A mismatch causes all CoA packets to be silently rejected.

Test Architecture

  • Each test gets a transactional session rolled back on teardown (fast, isolated)
  • SMS and HTTP calls are mocked with unittest.mock — no real gateway calls
  • conftest.py overrides the get_db FastAPI dependency automatically

Step 2 – Run Migrations

kubectl apply -f - <<EOF

  name: whisp-migrate

  template:

Troubleshooting

database_connection_failed on startup

docker compose exec api python -c \
  "import asyncpg, asyncio; asyncio.run(asyncpg.connect('$DATABASE_URL'))"

Common causes: wrong hostname (postgres inside Docker, localhost outside) · missing postgresql+asyncpg:// prefix · TimescaleDB extension not installed.

redis_unavailable_cannot_blacklist_token

docker compose exec redis redis-cli ping   # should return PONG

Non-fatal in dev but must be resolved in production — tokens remain valid after logout without Redis.

SMS not delivered

  1. Check notifications table: SELECT * FROM notifications WHERE status='failed' ORDER BY created_at DESC LIMIT 10;
  2. Check the error column for the raw gateway response
  3. Verify SMS_GATEWAY_API_KEY and SMS_GATEWAY_SENDER_ID are set
  4. Confirm sender ID is approved by SSL Wireless for your account
  5. Test the API directly (see §9)

CoA disconnect not working

  1. Verify MikroTik: /radius incoming print — confirm accept=yes
  2. Check UDP port 3799 is open: nc -u <nas-ip> 3799
  3. Check coa_commands table for success=false + error column
  4. Confirm nas_devices.secret matches the RouterOS RADIUS secret exactly

bKash callback not receiving

bKash requires BKASH_CALLBACK_URL to be publicly reachable over HTTPS. For local dev use a tunnel:

ngrok http 8000
# Set BKASH_CALLBACK_URL=https://<ngrok-subdomain>.ngrok.io/payments/bkash/callback

alembic.ini not found

Always run Alembic from the repo root, or pass -c:

alembic -c /home/user/whISP/alembic.ini upgrade head

Subscriber shows online but has no internet

RADIUS sync succeeded but CoA was not sent or was ignored. Check coa_commands table. Manually trigger:

docker compose exec coa-engine python -c "
from app.coa import send_disconnect
import asyncio
asyncio.run(send_disconnect('<nas-ip>', '<secret>', '<username>'))
"

Kafka consumer lag growing

docker compose exec kafka kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 \
  --group whisp-api \
  --describe

If LAG is growing check radius-consumer and notification service logs for errors.
